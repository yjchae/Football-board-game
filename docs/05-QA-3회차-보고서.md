> 대상: 카드 풋볼 리그 (팀 관리 · 카드 등록 · 자유 위치 · 경기 진행 · AI 연동 · 저장 · 홈 화면 앱)
> 방식: 코드 검토 → 결함을 **재현 테스트로 먼저 확인** → 수정 → 같은 테스트로 해결 확인 → 회귀 테스트로 고정

|---|---|---|---|

| 2회차 | 수정 검증 + 경계 상황 (무작위 경기 200판) | 2건 (보통 1, 경미 1) | 2건 |
| 3회차 | 수정 코드 재검토 + 전체 회귀 | 1건 (보통, 1회차 수정에서 생긴 구멍) | 1건 |

## 1회차 — 핵심 결함 탐색

| # | 등급 | 증상 | 원인 | 수정 |
|---|---|---|---|---|
| Q1 | 🔴 치명 | **후반 시작·킥오프 버튼을 두 번 누르면 경기가 전반 0분으로 돌아감** (아이들 연타) | 킥오프 처리에 "경기 전/하프타임에만" 조건이 없음 | 킥오프·재개는 해당 단계에서만 처리 |
| Q2 | 🔴 치명 | **저장 공간이 차면 선수가 화면에만 보이고 실제로 저장되지 않아 새로고침 시 사라짐** (경고 없음) | 카드 사진 때문에 localStorage(약 5MB) 한도 초과, 오류 무시 | IndexedDB로 이전(기존 데이터 자동 이전), 저장 실패 시 빨간 경고, 저장 데이터를 다 불러온 뒤 화면 표시 |
| Q3 | 🟠 주요 | 킥오프 전에 선발을 바꿔도 교체 횟수가 줄고, 빠진 선수는 다시 못 들어옴 | 경기 전 패널도 경기 중 교체 규칙 사용 | 킥오프 전에는 자유롭게 선발 변경 ("선발 정하기") |
| Q4 | 🟡 보통 | 부상 선수를 그대로 두면 매 구간마다 작전 타임이 다시 걸림 | 부상 상태가 남아 있으면 계속 판정 | 그 구간에 새로 다친 경우에만 한 번 알림 |

정상 확인: AI(응답 모킹)로 전체 경기, 엉터리 AI 응답 시 오프라인 대체, 팀을 잘못 적은 골 교정, 레드카드 처리, 퇴장 선수의 이후 장면 무시.

## 2회차 — 수정 검증 + 경계 상황

**무작위 경기 퍼즈 테스트** (`src/hooks/match.fuzz.test.ts`)
교체·위치 이동(경기장 밖 좌표 포함)·포메이션 변경·버튼 연타를 무작위로 섞어 **200경기** 진행, 매 동작마다 확인:
같은 선수 중복 없음 / 인원 ≤ 11−퇴장 / 교체 ≤ 5 / 나간 선수 재투입 없음 / 좌표 경기장 안 / 시계 역행 없음 / 반드시 90분 종료.
→ **위반 0건** (선수 7명·골키퍼 없는 팀 50경기 포함)

| # | 등급 | 증상 | 수정 |
|---|---|---|---|
| R2-1 | 🟡 보통 | 키 오류·한도 0·없는 모델처럼 **고칠 수 없는 AI 오류도 매 구간 다시 요청** → 같은 실패 반복 | 이런 오류는 그 경기 동안 오프라인 엔진으로 계속 (잠깐 사용량 초과·네트워크 오류는 다음 구간 재시도). 한도 0 상태에서 전반 AI 요청 3회 → 1회 |
| R2-2 | ⚪ 경미 | 하프타임에 같은 포메이션을 다시 누르면 "포메이션 변경" 기록이 중복 | 실제로 바뀔 때만 기록 |

정상 확인: 팀 삭제 후 경기 준비 화면, 선수 0명 팀 안내, iPhone SE 가로 넘침 0px, 아주 긴 팀 이름.
