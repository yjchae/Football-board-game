# 🎨 UI 설계자 — "감독 전술 노트" 화면 설계서

> 대상 기능: 경기 전(`phase === 'ready'`)과 하프타임(`phase === 'halftime'`)에 양 팀 감독이 **전술을 글로 적어 저장**하고, 그 글을 시뮬레이션에 반영한다. 한 기기를 번갈아 쓰는 **핫시트** 방식이다.
> 기준 문서: `docs/02-UI설계자-화면설계서.md` ("야간 경기장" 테마), `src/styles.css`, `src/screens/MatchScreen.tsx`, `src/components/MatchParts.tsx`
> 이 문서는 설계만 담는다. 코드(.tsx)는 개발자가 이 문서를 보고 작성한다.

## 0. 기존 디자인 시스템에서 확인한 것 (재사용 규칙)

| 항목 | 기존 자산 | 이번 기능에서의 사용 |
|---|---|---|
| 색 토큰 | `--bg`, `--bg-2`, `--surface`, `--surface-2`, `--line`, `--text`, `--muted`, `--accent`, `--accent-ink`, `--danger`, `--warn`, `--ok`, `--radius` | 새 색 토큰을 만들지 않는다. 팀 색은 기존처럼 인라인 `--team` 변수로 넘긴다 |
| 폰트 | `--font-display`(Black Han Sans), `--font-body`, `--font-num`(Chakra Petch) | 카드 팀 이름·시트 제목 = display, 글자수·HOME/AWAY 라벨 = num |
| 버튼 | `.btn`, `.btn--primary`, `.btn--ghost`, `.btn--xl`, `.btn--float`, `.btn--text` | 저장 = `btn btn--primary`, 취소 = `btn btn--ghost`, 킥오프 버튼은 그대로 |
| 상태 표시 | `.status`, `.status--ok/--warn/--error/--busy` | 카드 상태 배지는 별도 `.tcard__state`로 만들되 색 규칙은 `.status`와 동일하게 맞춘다 |
| 탭 | `.tabs` (TacticsPanel 홈/원정 전환) | 전술 노트는 탭이 아니라 **두 카드를 동시에** 보여 준다 (누가 저장했는지 한눈에 보이도록) |
| 단계 래퍼 | `.stage`, `.stage__title` | 섹션 제목에 `.stage__title` 재사용 |
| 모달 | `.modal`, `.modal__panel`, `.modal__head`, `.modal__foot` | 시트는 `.modal` 백드롭을 재사용하고, 패널만 `.tsheet`(바텀시트 변형)로 새로 만든다 |
| 팀 색 그라데이션 | `.tpicker`, `.team-head`의 `color-mix(in srgb, var(--team) N%, …)` | 카드·시트 헤더 배경에 같은 공식을 쓴다 |
| 애니메이션 | `@keyframes rise / pop / fade` + `prefers-reduced-motion` 전역 처리 | 시트 등장 = 새 `sheet-up`, 공개 카드 = 기존 `pop` |

**⚠️ 클래스 충돌 주의**
- `.chip`은 이미 **포지션 보드의 선수 칩**(드래그용, `touch-action: none`, `cursor: grab`)이 쓰고 있다. 빠른 선택 칩에 `.chip`을 쓰면 드래그 스타일이 섞인다. → 빠른 선택 칩은 **`.tchip`** 으로 쓴다. (모양은 기존 `.league-chip`과 같은 계열)
- `.tbadge`(전광판 팀 배지), `.tpicker`(팀 선택), `.tactics`(TacticsPanel)는 이미 있다. 새 클래스는 `.tboard`, `.tcard`, `.tsheet`, `.tchip`, `.treveal`만 쓰며 기존 클래스와 겹치지 않는 것을 확인했다.
- 기존 모달 4곳(PlayerEditor, RandomDraft, TeamScanner, TeamsScreen)은 ESC 닫기·포커스 트랩이 없다. 이번 시트는 이를 갖추고, 나중에 공통 훅(`useDialog`)으로 뽑아 다른 모달에도 쓰도록 제안한다.

## 3. 컴포넌트 구조

```
LiveMatch (MatchScreen.tsx)
 ├ Scoreboard
 ├ [ready]    TacticsBoard half=1 ──┬ TacticCard side="home"
 │                                  ├ TacticCard side="away"
 │                                  └ TacticEditorSheet (열렸을 때만, 포털)
 │            TacticsPanel (기존)
 │            [킥오프] → confirmMissingTactics()
 ├ [halftime] HalfSummaryCard, HighlightReel
 │            TacticsBoard half=2  (위와 동일 구조)
 │            TacticsPanel (기존)
 │            [후반 시작] → confirmMissingTactics()
 └ [fulltime] FinalBanner
              TacticReveal
              …기존 요약/하이라이트
```

파일 위치 제안: `src/components/TacticNotes.tsx` 한 파일에 4개 컴포넌트 + 상수(`TACTIC_CHIPS`, `TACTIC_MAX`). MatchParts.tsx는 이미 300줄이라 분리한다.

### 3-1. 데이터 모양 (UI가 기대하는 형태)

```ts
type Half = 1 | 2;

/** 한 팀의 전술 노트 */
interface TacticNote {
  first?: string;        // 전반 전술 (ready에서 저장)
  second?: string;       // 후반 전술 (halftime에서 "저장"을 눌렀을 때만 존재)
}

/** 경기 상태에 추가 (useMatch state) */
tactics: Record<Side, TacticNote>;
```

**하프타임 판정 규칙 (UI 표시 기준)**
- `second === undefined` → "전반 전술 유지" 상태 (시뮬레이션은 `first`를 계속 사용)
- `second !== undefined` → "후반 전술 저장됨" (내용이 전반과 같아도 감독이 확인했으므로 저장됨으로 본다)

### 3-2. Props 제안

```ts
/** 두 팀 카드 + 작성 시트를 관리하는 섹션 */
interface TacticsBoardProps {
  sides: { home: MatchSide; away: MatchSide };
  tactics: Record<Side, TacticNote>;
  half: Half;                                    // 1 = 경기 전, 2 = 하프타임
  onSave(side: Side, half: Half, text: string): void;
}
// 내부 상태: editing: Side | null  (어느 팀 시트가 열렸는지)
//          lastOpener: HTMLElement | null (닫을 때 포커스 복귀용)

/** 팀 카드 1장 (카드 전체가 <button>) */
interface TacticCardProps {
  side: Side;
  team: Team;                                    // 이름, emoji, color
  status: TacticStatus;
  onOpen(): void;
}
type TacticStatus =
  | 'empty'      // 미작성 (ready: first 없음 / halftime: first도 second도 없음)
  | 'saved'      // ready: first 저장됨
  | 'kept'       // halftime: first만 있음 → "전반 전술 유지"
  | 'resaved';   // halftime: second 저장됨

/** 작성 시트 */
interface TacticEditorSheetProps {
  side: Side;
  team: Team;
  half: Half;
  initialText: string;          // half=1: first ?? ''  /  half=2: second ?? first ?? ''
  prefilledFromFirst: boolean;  // half=2이고 second가 없을 때 true → 안내문 표시
  maxLength?: number;           // 기본 200
  onSave(text: string): void;   // 앞뒤 공백 trim 후 전달. 빈 문자열이면 "작전 지우기"로 처리
  onClose(): void;
}

/** 종료 화면 공개 카드 */
interface TacticRevealProps {
  sides: { home: MatchSide; away: MatchSide };
  tactics: Record<Side, TacticNote>;
}
```

상태 계산 헬퍼 (순수 함수, 테스트 쉬움):

```ts
function tacticStatus(note: TacticNote, half: Half): TacticStatus {
  if (half === 1) return note.first ? 'saved' : 'empty';
  if (note.second !== undefined) return 'resaved';
  return note.first ? 'kept' : 'empty';
}
```

### 3-3. 빠른 선택 칩 동작

```ts
const TACTIC_CHIPS = [
  { id: 'attack',   label: '공격적',   emoji: '🔥' },
  { id: 'defend',   label: '수비적',   emoji: '🛡️' },
  { id: 'counter',  label: '역습',     emoji: '⚡' },
  { id: 'possess',  label: '점유율',   emoji: '🔄' },
  { id: 'press',    label: '강한 압박', emoji: '💪' },
  { id: 'wing',     label: '측면 공격', emoji: '↗️' },
  { id: 'center',   label: '중앙 돌파', emoji: '⬆️' },
  { id: 'longball', label: '롱볼',     emoji: '🚀' },
] as const;
```

- 누르면 **문장 끝에 덧붙인다**. 규칙: 현재 글이 비었으면 `라벨`, 아니고 끝이 `. ! ? ,` 또는 공백이면 `+ ' ' + 라벨`, 그 외엔 `+ ', ' + 라벨`. → "측면 공격, 강한 압박"
- 덧붙인 결과가 200자를 넘으면 붙이지 않고 칩을 잠깐 흔들며(`tchip--deny`) 글자수 영역에 `더 넣을 자리가 없어요` 표시.
- 칩은 토글이 아니다(같은 칩을 두 번 누르면 두 번 붙는다). 다만 이미 글에 그 라벨이 들어 있으면 칩에 체크 표시(토글이 아니므로 `aria-pressed`는 쓰지 않고 `tchip--used` 클래스만)로 "썼어요"를 보여 준다.
- 칩을 누른 뒤 포커스는 칩에 남기고, textarea 커서는 끝으로 옮긴다(연속으로 여러 칩을 누르기 쉽도록).

## 4. 상태별 카드 모습

| 상태 | 언제 | 배지(.tcard__state) | 보조 문구 | CTA | 카드 스타일 |
|---|---|---|---|---|---|
| `empty` (ready) | 경기 전, 미작성 | `✏️ 아직 작전이 없어요` (warn 색) | `눌러서 우리 팀 작전을 적어요` | `작전 쓰기 →` | 테두리 **점선**(`--line`), 배경 흐림 → "할 일" 느낌 |
| `saved` (ready) | 경기 전, 저장 완료 | `🔒 전술 저장됨` (ok 색) | `내용은 비밀이에요` | `고치기 →` | 실선 팀 색 테두리, 팀 색 그라데이션 |
| `empty` (halftime) | 전반에도 안 씀 | `✏️ 아직 작전이 없어요` | `후반 작전을 적어 볼까요?` | `작전 쓰기 →` | ready의 empty와 동일 |
| `kept` (halftime) | 전반 전술만 있음 | `↩️ 전반 전술 유지` (muted/중립) | `그대로 두면 전반 작전으로 뛰어요` | `후반 작전 쓰기 →` | 실선이지만 **팀 색 20% 약하게**, 배지에 `1ST` 숫자 태그 |
| `resaved` (halftime) | 후반 전술 저장 | `🔒 후반 전술 저장됨` (ok 색) | `내용은 비밀이에요` | `고치기 →` | saved와 동일 + `2ND` 숫자 태그 |

공통 규칙
- **카드에는 절대 전술 내용을 노출하지 않는다** (첫 글자, 글자수, 칩 아이콘도 노출 금지 — 핫시트 비밀 보장).
- 색만으로 상태를 전달하지 않는다: 아이콘 + 문구 + 테두리 모양(점선/실선)을 같이 바꾼다 (02 문서 5장 원칙).
- 저장 직후 해당 카드에 0.4초 `pop` + 배지 반짝임 1회. 동시에 보드 하단 `aria-live` 영역에 "사자 FC 전술이 저장됐어요" 읽어 줌.
- 저장된 카드를 누르면 바로 시트가 열리지 않고, **확인 단계**를 먼저 보여 준다(4-1).

### 4-1. 저장된 카드 다시 열기 (핫시트 보호)

저장된 카드(`saved` / `resaved` / `kept`) 클릭 시 시트 안 내용을 바로 보이지 않고 **가림막 화면**부터 띄운다.

```
┌──────────────────────────────────────┐
│ 🦁 사자 FC                          [✕] │
│                                      │
│        🙈                            │
│   사자 FC 감독님만 열어 주세요!          │
│   상대 감독은 잠깐 화면을 보지 마세요.     │
│                                      │
│     [ 취소 ]   [ 👀 내가 감독이에요, 열기 ] │
└──────────────────────────────────────┘
```

- 같은 `TacticEditorSheet` 안의 `stage: 'guard' | 'edit'` 내부 상태로 처리 (컴포넌트 추가 없음).
- `empty` 카드는 가림막 없이 바로 `edit` 단계로 연다(쓸 내용이 없으므로 비밀 아님). 단, `.tsheet__secret` 안내 띠는 항상 보인다.
- 하프타임 `kept` 카드도 전반 내용이 미리 채워지므로 가림막을 거친다.

## 5. 킥오프 / 후반 시작 확인 문구

`window.confirm`을 쓴다(기존 "경기를 그만둘까요?"와 같은 방식, e2e에서 `page.on('dialog')`로 처리 가능).

| 상황 | 문구 |
|---|---|
| 경기 전, 한 팀 미작성 | `🦁 사자 FC는 아직 작전을 안 적었어요.\n작전 없이 킥오프할까요?` |
| 경기 전, 두 팀 모두 미작성 | `두 팀 모두 아직 작전을 안 적었어요.\n작전 없이 킥오프할까요?` |
| 하프타임, 한 팀이 `kept` | `🦁 사자 FC는 전반 작전 그대로 뛰어요.\n이대로 후반을 시작할까요?` |
| 하프타임, 한 팀이 `empty` | `🦁 사자 FC는 작전이 없어요.\n이대로 후반을 시작할까요?` |
| 하프타임, 두 팀 모두 해당 | 두 팀 이름을 줄바꿈으로 나열 + `이대로 후반을 시작할까요?` |

- 취소를 누르면 아무 일도 없고, 포커스를 첫 번째 미작성 카드로 옮긴다(`scrollIntoView({ block: 'center' })` + focus).
- 모든 팀이 `saved`/`resaved`면 confirm 없이 바로 진행.
- 킥오프 버튼 옆(위)에 작은 미리 알림을 둔다: `.tboard__progress` — `✅ 2 / 2 팀 준비 완료` 또는 `✏️ 1팀이 아직 작전을 안 적었어요`. confirm이 갑작스럽지 않도록.

## 6. 접근성

### 6-1. TacticsBoard / TacticCard
- 섹션: `<section aria-labelledby="tboard-title">`, 제목 `<h3 id="tboard-title" class="stage__title">`.
- 카드: `<button type="button" class="tcard">` 전체가 하나의 버튼. 접근 가능한 이름은 `aria-label`로 조합:
  - empty: `"사자 FC 홈 팀 작전 쓰기, 아직 작전이 없어요"`
  - saved: `"사자 FC 홈 팀 작전 고치기, 전술 저장됨"`
  - kept: `"사자 FC 홈 팀 후반 작전 쓰기, 전반 전술 유지 중"`
- `aria-haspopup="dialog"`, 시트가 열려 있을 때 `aria-expanded="true"`.
- 저장 알림: 보드 하단 `<p class="sr-only" aria-live="polite">`.
  - `.sr-only` 유틸은 현재 styles.css에 없으므로 새로 추가(8장 CSS 포함).

### 6-2. TacticEditorSheet (다이얼로그)
- 백드롭 `<div class="modal tsheet-backdrop">` + 패널 `<div class="tsheet" role="dialog" aria-modal="true" aria-labelledby="tsheet-title" aria-describedby="tsheet-secret">`.
- **포커스 트랩**: 열릴 때 포커스 이동 대상
  - guard 단계 → "열기" 버튼
  - edit 단계 → textarea (커서는 글 끝)
  - Tab / Shift+Tab은 시트 안의 포커스 가능 요소(닫기 ✕, 칩 8개, textarea, 취소, 저장) 사이에서 순환.
  - 구현 제안: 패널의 첫/끝 포커스 요소에서 `keydown` Tab 가로채기 (외부 라이브러리 없이). 배경 `.app`에는 `inert` 속성 부여(지원 브라우저) — 미지원 시 트랩만으로 충분.
- **ESC 닫기**: `keydown Escape` → 취소와 동일. 단, 글이 바뀌었으면(`dirty`) `confirm('적던 작전이 사라져요. 닫을까요?')`.
- 백드롭 클릭 = 취소와 동일(기존 모달 패턴 `onClick={onClose}` 유지, 패널은 `stopPropagation`).
- **닫힌 뒤 포커스 복귀**: 시트를 연 카드 버튼으로 돌려 놓는다.
- textarea
  - `<label for="tactic-text">` = `작전 메모` (시각적으로 보이게 둔다. 아이들에게 설명이 됨)
  - `maxLength={200}` (브라우저가 하드 제한) + `aria-describedby="tactic-count tactic-hint"`
  - 글자수 `<span id="tactic-count" aria-live="polite">`: 매 입력마다 읽으면 시끄러우므로 **180자 이상일 때만** 문구를 `"남은 글자 20자"`로 바꿔 읽게 한다(평소엔 `aria-live="off"`와 같은 효과가 나도록 텍스트를 시각용 `aria-hidden` 숫자 + 스크린리더용 조건부 문구로 분리).
- 칩: `<button type="button" class="tchip">` + `aria-label="공격적 덧붙이기"`. 칩 묶음은 `<div role="group" aria-label="빠르게 고르기">`.
- 저장 버튼: 글이 비어 있으면 저장 대신 `🗑️ 작전 지우기`로 바뀐다(이미 저장된 작전이 있을 때만). 처음부터 빈 상태면 `disabled` + `title="한 글자 이상 적어 주세요"`.
- 키보드 단축: `Ctrl/⌘ + Enter` = 저장 (선택 사항, 시트 하단에 `small muted`로 표기하지 않음 — 아이용이라 생략 가능).

### 6-3. TacticReveal
- `<section aria-labelledby="treveal-title">`, 각 팀은 `<article>`, 전/후반은 `<dl>`(`<dt>전반</dt><dd>…</dd>`).
- "유지" 표시는 텍스트로도 읽히게: `<dd>전반 전술 유지</dd>`.

### 6-4. 공통
- 터치 영역 최소 44px (카드, 칩, 버튼 모두).
- 대비: `--muted`(#8fa99a) on `--surface`(#10291c) ≈ 5.9:1, `--warn` on surface ≈ 9:1 → AA 통과. 팀 색은 배경 장식에만 쓰고 글자색에는 쓰지 않는다(팀 색이 어두울 수 있음).
- `prefers-reduced-motion`: 전역 규칙이 이미 있음. 시트는 슬라이드 대신 즉시 표시가 된다.

## 7. 모바일 360px 대응

| 요소 | > 560px | ≤ 560px (360px 기준 확인) |
|---|---|---|
| `.tboard__grid` | 2열 (`1fr 1fr`), gap 14px | 1열, gap 10px |
| `.tcard` | 세로 배치, 최소 높이 150px, 엠블럼 2.4rem | 가로 2줄 배치, 최소 높이 76px, 엠블럼 1.8rem, 이름 말줄임 |
| `.tsheet` | 가운데 모달 `min(560px, 100%)`, radius 24px | **바텀시트**: 화면 하단 고정, 폭 100%, 위쪽 radius만 24px, `max-height: 92dvh`, 상단 grab bar |
| 시트 패딩 | 22px | 16px + `env(safe-area-inset-bottom)` |
| textarea | 5줄 | 4줄, `font-size: 16px` 이상 (iOS 확대 방지) |
| 칩 | 한 줄에 4개 정도, 줄바꿈 | **가로 스크롤 1줄** (`overflow-x: auto`, `scroll-snap`) → 키보드가 올라와도 textarea가 가려지지 않게 높이 절약 |
| 시트 버튼 | 오른쪽 정렬 | 취소/저장 각 50% 폭, 저장이 오른쪽 (엄지 위치) |
| `.treveal__grid` | 2열 | 1열 |
| `.tboard__progress` | 가운데 정렬 | 그대로 (한 줄 34자 이내 문구 유지) |

- 360px에서 페이지 가로 스크롤이 생기지 않도록 모든 그리드 자식에 `min-width: 0`.
- 키보드가 올라왔을 때: 바텀시트는 `position: fixed; bottom: 0` + `max-height: 92dvh`라서 `dvh`가 키보드를 반영한다. 미지원 브라우저용으로 `92vh` 폴백 선언을 먼저 둔다.
- 기존 `.btn--float`(킥오프 버튼, z-index 5)와 `.topbar`(z-index 20)보다 시트가 위에 있어야 하므로 시트 백드롭은 기존 `.modal`(z-index 100)을 그대로 쓴다. 하이라이트 `.spotlight`(90)는 ready/halftime에 안 나오므로 충돌 없음.

3. 하프타임 → `tactic-card-home[data-status=kept]` → 클릭 → `tactic-guard-open` → `tactic-textarea` 값이 전반 글과 동일, `tactic-prefill-note` 존재.

6. 시트 열린 상태에서 `Escape` → `tactic-sheet` 사라짐, 포커스가 `tactic-card-home`으로 복귀.
