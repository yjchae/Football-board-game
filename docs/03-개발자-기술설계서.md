# 💻 개발자 — 기술 설계서

## 1. 스택
React 19 · TypeScript · Vite · zustand(상태+localStorage 저장) · @dnd-kit/core(드래그앤드롭) · @google/genai(제미나이) · @anthropic-ai/sdk(클로드) · Vitest · Playwright

## 2. 폴더 구조 (가독성 원칙: 화면 / 순수 로직 / AI 분리)

```
src/
├─ domain/            ← 순수 게임 로직 (React 의존 없음, 테스트 대상)
│  ├─ types.ts         데이터 타입
│  ├─ formations.ts    포메이션 좌표, 자동 배치, 포메이션 변경
│  ├─ lineupOps.ts     드래그/탭 이동 규칙 (교체 횟수·재투입 금지·퇴장)
│  ├─ match.ts         구간 정의, 경기 컨텍스트, 점수/통계 계산, 팀 전력
│  └─ localEngine.ts   오프라인 시뮬레이터 (시드 난수 주입 가능)
├─ ai/
│  ├─ providers.ts     제미나이/클로드 호출 (SDK 지연 로딩)
│  ├─ prompts.ts       경기·카드 판독 프롬프트
│  ├─ parse.ts         AI 응답 검증/정리 (가짜 선수·잘못된 시간 차단)
│  └─ engine.ts        설정 → 엔진 생성, AI 실패 시 오프라인 대체
├─ hooks/useMatch.ts   경기 상태 머신 (useReducer)
├─ store/              zustand 스토어 + 연습용 팀
├─ components/         PlayerCard, PlayerEditor, LineupBoard, MatchParts
├─ screens/            TeamsScreen, MatchScreen, SettingsScreen
└─ utils/              이미지 압축, 조사(이/가) 처리, id
```

## 3. 경기 상태 머신 (`hooks/useMatch.ts`)

```
ready ──KICKOFF──▶ playing ──(구간 끝 & 작전타임 요청/부상)──▶ timeout ──RESUME──▶ playing
                     │
                     ├─(45분)──▶ halftime ──KICKOFF(후반 시작)──▶ playing
                     └─(90분)──▶ fulltime
```
`playing` 내부 루프: ① 구간 이벤트 요청(FETCH) → ② 이벤트를 `playbackMs` 간격으로 하나씩 공개(REVEAL) → ③ 큐가 비면 SEGMENT_END.
StrictMode 중복 요청 방지를 위해 `requested` ref로 구간 인덱스를 기억한다.

## 4. AI 연동

| 항목 | 제미나이 | 클로드 |
|---|---|---|
| SDK | `@google/genai` `models.generateContent` | `@anthropic-ai/sdk` `beta.messages.create` (브라우저 직접 호출: `dangerouslyAllowBrowser`) |
| 기본 모델 | `gemini-2.5-flash` (설정에서 변경 가능) | `claude-opus-5-5` (Sonnet 5.5 / Haiku 5.5 선택 가능) |
| JSON 강제 | `responseMimeType: application/json` | 프롬프트 지시 + 검증기 |
| 속도 | 기본 | `effort: low` (아이들 대기 시간 단축) |
| 거절 대응 | — | 서버 측 `fallbacks: "default"` + `stop_reason: refusal` 확인 |
| 카드 판독 | 이미지 inlineData | 이미지 base64 블록 |

> 제미나이 기본 모델명은 제 학습 기준의 이름이며, 시점에 따라 바뀔 수 있어 설정 화면에서 직접 수정할 수 있게 했습니다. [보통 확신 – 검증 권장]

### 응답 검증 규칙 (`ai/parse.ts`)
- 코드블록/잡담이 섞여도 JSON만 추출
- 허용된 이벤트 타입만 통과, 이벤트 최대 14개
- 경기장에 **없는 선수 id → 제거**, 반대 팀으로 적힌 선수 → 실제 팀으로 교정
- 득점자 없는 골 → 무효
- 분(minute)은 해당 구간 범위로 고정
- 점수는 AI 숫자가 아닌 **goal 이벤트 개수**로 계산

## 5. 저장
- `localStorage['card-football-v1']` 에 팀·선수·설정 저장
- 카드 사진: 썸네일 320px JPEG(약 15~30KB)로 저장, AI 판독용 1280px 이미지는 메모리에서만 사용

npx vite preview --port 4173 & npm run e2e   # 브라우저 E2E
