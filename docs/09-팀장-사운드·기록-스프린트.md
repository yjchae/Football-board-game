| 상황 | 효과음 | 음성 해설 |

| 퇴장 | — | 끊고 바로 |
| 그 밖의 장면 | — | 중계 문장 (이모지 제거) |

- 설정에서 **효과음 / 음성 해설**을 각각 켜고 끌 수 있고, 경기 화면 🔊 버튼으로 둘 다 한 번에 끄고 켠다. 기본값은 둘 다 켜짐.

### 2-4. 경기 기록
- 경기가 **끝까지 끝났을 때만** 저장 (중간에 나간 경기는 저장 안 함).
- 저장 내용: 종료 시각, 두 팀 이름·엠블럼·색, 점수, 득점자(분·이름·팀). 팀을 나중에 지워도 기록은 그대로 보인다.
- **최근 10경기**만 유지 (최신이 맨 위). 같은 경기는 한 번만 저장. "기록 지우기"로 전부 삭제(확인창).

## 4. 💻 개발자 — 핵심 결정 (ADR)

### ADR-8. 소리는 음원 파일 없이 브라우저 기능으로
- **효과음**: Web Audio API로 합성 (휘슬 = 2750Hz 사인파 + 32Hz 떨림, 함성 = 대역 통과 잡음, 나팔 = 톱니파 4음). 저작권 걱정 없고, 앱 용량이 늘지 않으며 오프라인(PWA)에서도 동작.
- **음성 해설**: Web Speech API(`speechSynthesis`)의 한국어 목소리. 기기마다 목소리 품질이 다르다. [보통 확신 – 실기기 검증 권장]
- **AI 남자 목소리** (후속 변경): 아이폰·아이패드엔 한국어 남자 목소리가 없어서, 제미나이 키가 있으면 제미나이 음성 합성(`Fenrir` 목소리)으로 해설을 만들어 Web Audio로 재생한다 (`src/audio/cloudVoice.ts`). 앞 문장을 읽는 동안 다음 문장을 미리 받고, 같은 문장은 최근 40개까지 기억한다. 키 오류·모델 없음이면 그 접속 동안, 사용량 초과면 1분 동안 기기 목소리로 대신 읽는다. 기기 목소리도 남자 목소리 이름을 우선 고르고, 없으면 톤을 낮춘다. 설정 › 소리의 `toggle-ai-voice`·`voice-test`. [보통 확신 – 실기기·실제 키로 검증 필요]
- **자동재생 정책**: 브라우저는 사용자가 누른 순간에만 소리를 켤 수 있어 `킥오프`·`후반 시작` 버튼 클릭 안에서 `unlockSfx()`·`unlockNarration()`을 부른다.
- **이벤트 → 소리 규칙**은 순수 함수 `soundFor()`로 분리해 단위 테스트. 휘슬 판단은 문장이 아닌 이벤트의 `cue` 필드(`kickoff`/`second-half`/`halftime`/`fulltime`)로 한다.
- **해설과 속도 맞추기**: `useMatch`가 `isBusy()`를 받아, 낭독 중이면 200ms씩 미루며 최대 8초 기다린다.

### ADR-9. 경기 기록은 기존 저장소(IndexedDB)에 함께
- zustand `history` 필드로 팀·설정과 같은 저장소에 보관. 예전 저장 데이터에는 `history`가 없으므로 불러올 때 빈 배열로 채운다.

## 5. 🧪 QA — 결과

| 명령 | 결과 |
|---|---|
| `npx tsc -b` | ✅ 오류 0 |
| `npx vitest run` | ✅ 14개 파일, 175 통과 / 1 생략 (기존 163 + 신규 12) |
| `npm run build` | ✅ |
| `npm run e2e` | ✅ 기존 5개 스크립트 전부 통과 + 신규 `sound-history` **23/23** |

신규 e2e 확인 항목 (AudioContext·speechSynthesis를 가짜로 바꿔 재생 기록을 검사):
- 속도 5단계 표시·선택, 소리 스위치 기본값·끄기
- 랜덤 뽑기에 세 리그 노출
- 한 경기 휘슬 정확히 7번(1+2+1+3), 골 함성 수 = 골 수, 킥오프·골·종료 해설, 해설 문장에 이모지 없음
- 음소거 시 휘슬·해설 없음
- 11경기 후 기록 10건, 새로고침 후에도 10건, 기록 지우기
- 낭독(1.5초) 중에는 재생 간격 40ms여도 다음 장면이 나오지 않음
